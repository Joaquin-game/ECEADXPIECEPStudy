    Correctness note
    Built-in generators calculate answers directly from the same formulas used in their explanations. Custom generators use your expression as the answer key; the app validates the syntax and ranges but cannot prove your formula describes the intended math problem. Preview several versions before sharing it with the team.

    Generator spec editor

    JSON is validated before it is saved. This is a declarative generator format, not arbitrary JavaScript.

    Paste one generator object or an array of objects. Use "variables":{"a":{"min":1,"max":9}}, "answer":"a^2 + x_prev" for numeric modes, or "mode":"id","answer":"Laplace transform","acceptedAnswers":["LT"] for identification. For true/false use "mode":"tf","answer":"a-3" (positive is True, zero/negative False). Use optional "steps":[...] for a legacy linear numeric sequence.

    Generator spec guide

    Valid fields for a single question or dependent sequences.

    Single generator

    Use title, category, variables, prompt, answer, and explanation. Modes are mixed, mc, fib, id (text identification), and tf (true/false). For id, answer is the term and optional acceptedAnswers is an array of aliases. For tf, answer can be literal true/false or a numeric expression: positive means True, zero/negative means False. Numeric modes may also use format, distractors, dependsOnPrevious, expectedNotation (scientific/engineering/decimal), absoluteTolerance, relativeTolerance, significantDigits, and decimalPlaces.

    Custom dependency sequence

    Use a root title and a steps array. Each step has a category, variables, prompt, answer, and explanation. A later step can use x_prev (or legacy prev) in its answer formula. In the prompt, declare \(x_{\mathrm{prev}}\) as the previous step’s numeric result. Use {{x_prev}} to insert its current numeric value into prompt/explanation text. If Step 1 changes, Step 2 recalculates and supports follow-through scoring.

    Categories

    laplace, ztrans, fourier, convolution, controls, signals, complexcalc, ode, vector, calculus, related, relativity, advanced, em, econ, data, geas, electronics, precalc, probability.

    Expression functions

    Arithmetic operators, parentheses, sqrt, abs, sin, cos, tan, exp, log/ln, floor, ceil, round, min, max, pi, and e. Expressions are evaluated by a restricted math parser, not eval().

    Example: a parent question outputs a value; the next step uses x_prev/(1+x_prev*H), with H sampled from its own variable range. The code editor accepts JSON only and checks required fields. Identification generators use a text answer; true/false generators use true/false or a numeric truth expression.
